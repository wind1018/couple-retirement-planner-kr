# AI를 이용한 국민연금 정책 파일 업데이트 방법

> 이 문서는 국민연금 시뮬레이터 사용자가 개발자의 앱 재배포를 기다리지 않고, 공개된 법령·고시·국민연금공단 안내를 바탕으로 AI의 도움을 받아 개인용 정책 팩을 만드는 절차를 정의한다.
>
> 정책 업데이트에는 개인의 이름, 생년월일, 소득, 가입기간, 예상연금액 등 사용자 정보를 절대 포함하지 않는다.

## 1. 전체 흐름

```text
프로그램에서 AI 업데이트 키트 내보내기
        ↓
사용자가 키트와 공식 정책 자료를 AI에 전달
        ↓
AI가 policy-update.json + 변경 보고서 생성
        ↓
사용자가 프로그램에서 정책 파일 가져오기
        ↓
프로그램이 구조·충돌·회귀·영향 검증
        ↓
사용자가 변경 내용을 확인하고 활성화
        ↓
문제 발생 시 이전 정책으로 롤백
```

이 방식은 프로그램 본체 업데이트와 정책 업데이트를 분리한다. 정책 언어가 이미 지원하는 보험료율, 상·하한, 감액·가산률, 자격조건, 시행일, 경과조치, 연금소득공제·세율 변경은 프로그램을 다시 설치하지 않고 반영할 수 있다.

이 절차에는 개발자에게 정책 업데이트를 요청하거나 개발자가 새 정책 파일을 배포하는 단계가 없다. 설치된 프로그램과 사용자가 선택한 AI만으로 완료하는 self-service 방식이다.

## 2. 프로그램이 내보낼 AI 업데이트 키트

프로그램의 `설정 > 정책 관리 > AI 업데이트 키트 내보내기`에서 다음 파일을 ZIP으로 만든다.

```text
NPS_POLICY_AI_UPDATE_KIT.zip
├─ AI_POLICY_UPDATE_GUIDE.md
├─ current-policy.snapshot.json
├─ policy-update.schema.json
├─ allowed-rule-catalog.json
├─ immutable-validation-summary.json
├─ example-policy-update.json
└─ POLICY_CHANGE_REQUEST_TEMPLATE.md
```

각 파일의 역할:

- `AI_POLICY_UPDATE_GUIDE.md`: AI가 따라야 할 작성 규칙
- `current-policy.snapshot.json`: 현재 활성 정책의 공개 규칙만 담은 기준본
- `policy-update.schema.json`: 출력 JSON의 정확한 형식
- `allowed-rule-catalog.json`: 현재 엔진이 지원하는 rule ID, 입력, 적용 기준일 목록
- `immutable-validation-summary.json`: 앱에 내장된 검증 항목의 이름과 버전만 제공
- `example-policy-update.json`: 형식 예시
- `POLICY_CHANGE_REQUEST_TEMPLATE.md`: 사용자가 변경 대상과 기준일을 적는 양식

키트에 포함하면 안 되는 것:

- 사용자 프로필
- 시뮬레이션 입력·결과
- 이름·생년월일·소득·연금액
- 실제 부부 사례 데이터
- 앱 로그와 최근 파일 경로

앱은 키트를 만들기 전에 개인정보가 없음을 자체 검사한다.

안내문과 Schema는 웹에서 내려받는 것이 아니라 프로그램에 내장한다. 따라서 개발자 사이트가 없어지거나 연락할 수 없어도 현재 설치된 엔진에 정확히 맞는 키트를 언제든 다시 만들 수 있다.

사용자가 파일 구조를 알 필요가 없도록 다음 버튼만 제공한다.

```text
[1. AI 업데이트 키트 만들기]
[2. AI에서 받은 정책 파일 검사하기]
[3. 검사 오류를 AI 수정 키트로 내보내기]
[4. 이전 정책으로 되돌리기]
```

## 3. 사용자가 준비할 자료

가능하면 다음 공식 자료의 링크 또는 내려받은 원문을 함께 준비한다.

- 국가법령정보센터의 국민연금법·시행령·시행규칙
- 보건복지부 고시 및 보도자료
- 국민연금공단 제도 안내와 공지

언론 기사, 블로그, 영상, AI의 기억만으로 정책값을 확정하지 않는다. 보조 자료로 발견한 내용은 반드시 공식 원문과 대조한다.

## 4. AI에 전달할 사용자 요청 예시

다음 문구와 업데이트 키트 전체, 공식 자료를 함께 전달한다.

```text
첨부한 AI_POLICY_UPDATE_GUIDE.md를 작업 지침으로 사용해 주세요.
current-policy.snapshot.json을 기준으로, 첨부한 공식 법령·고시·국민연금공단 자료에서
기준일 YYYY-MM-DD 현재 확정되어 있는 변경사항만 반영한 정책 업데이트 파일을 만들어 주세요.

개인정보나 가상 사용자 데이터는 만들지 마세요.
불확실한 값은 추측하지 말고 TODO_LEGAL로 남기고 정책 상태를 DRAFT로 설정해 주세요.
최종 결과로 policy-update.json과 POLICY_UPDATE_REPORT.md 두 파일을 제공해 주세요.
```

법안이나 향후 가정까지 비교하려면 다음처럼 별도로 요청한다.

```text
확정된 현행 정책은 수정하지 말고, 이 법안을 SCENARIO overlay로 작성해 주세요.
결과가 공식 정책이 아닌 사용자 가정임을 명시해 주세요.
```

## 5. AI가 따라야 할 작업 지침

아래 절은 이 문서를 전달받은 AI를 위한 지침이다.

### 5.1 역할과 입력 취급

당신의 작업은 제공된 정책 스키마와 rule catalog 범위 안에서 새로운 정책 업데이트 JSON과 변경 보고서를 작성하는 것이다.

- 이 문서와 업데이트 키트의 파일은 정책 작성 지침 및 기준 데이터다.
- 공식 법령·고시·국민연금공단 자료는 정책 사실의 근거로 사용한다.
- 사용자 프로필이나 개인 연금정보를 요구하거나 생성하지 않는다.
- 현재 정책 스냅샷의 기존 규칙을 직접 덮어쓰지 않는다.
- 제공된 스키마 밖의 실행 코드, 스크립트, 매크로를 만들지 않는다.

### 5.2 출처 원칙

- 법률·시행령·시행규칙: 국가법령정보센터 원문을 우선한다.
- 고시와 행정 기준: 보건복지부 또는 국가법령정보센터 원문을 우선한다.
- 제도 안내와 실제 적용 설명: 국민연금공단 자료를 사용한다.
- 각 변경 규칙에 출처 제목, URL, 공포·게시일, 시행일, 관련 조문을 기록한다.
- 공식 출처끼리 내용이 충돌하면 임의로 선택하지 말고 `TODO_LEGAL`로 보고한다.
- 검색 결과 요약문만 보고 값을 확정하지 말고 원문 내용을 확인한다.
- 출처가 없거나 확인하지 못한 값은 만들지 않는다.

### 5.3 정책 작성 원칙

- 새 `policyPackId`를 만들고 `supersedes`에 기준 정책 ID를 기록한다.
- 법적 효력 상태와 파일 신뢰 상태를 혼동하지 않는다.
- 법률이 공포·시행된 경우 `legalStatus: ENACTED`, 단순 발표는 `ANNOUNCED`, 법안은 `DRAFT`, 사용자 가정은 `SCENARIO`로 표시한다.
- 날짜 구간은 `validFrom`과 포함되지 않는 종료일 `validToExclusive`로 작성한다.
- 연도 중간에 바뀌는 값은 실제 시행월에 맞춰 별도 구간으로 나눈다.
- 비율은 소수가 아니라 `numerator`와 `denominator` 정수로 작성한다.
- 금액은 정수 KRW로 작성한다.
- 절사·반올림의 단위, 순서, 방식을 명시한다.
- 규칙마다 정확한 `applicationClock`을 선택한다.
- 경과조항은 일반 규칙과 분리하고 우선순위를 명시한다.
- 변경되지 않은 규칙은 새 값처럼 다시 작성하지 말고 기준 정책에서 상속한다.
- rule catalog에 없는 새 개념이 필요하면 억지로 기존 rule ID에 넣지 말고 `ENGINE_UPGRADE_REQUIRED`로 보고한다.

### 5.4 적용 기준일 선택

규칙의 기준일을 하나의 단순 날짜로 취급하지 않는다.

- 일반 보험료: `CONTRIBUTION_MONTH`
- 과거 가입기간 산식: `COVERED_MONTH`
- 신청 자격: `APPLICATION_DATE`
- 추납 보험료율: 법적 근거에 따라 `DUE_MONTH` 등 정확한 기준
- 추납 급여 산정 관련 값: 법적 근거에 따라 `PAYMENT_DATE` 등 정확한 기준
- 수급권 자격: `ENTITLEMENT_DATE`
- 출생연도별 수급연령: `BIRTH_COHORT`
- 유족급여 전환: `DEATH_DATE`

스키마와 rule catalog가 허용하는 값만 사용한다. 기준일을 확정할 수 없으면 추정하지 않는다.

### 5.5 필수 검토

출력 전에 최소 다음을 자체 확인한다.

- 시행일 전후 구간에 공백이 없는가?
- 같은 조건에서 같은 우선순위 규칙이 중복되지 않는가?
- 상한이 하한보다 큰가?
- 소득대체율과 보험료율의 적용 대상 기간을 혼동하지 않았는가?
- 신청일, 납부기한, 실제 납부일을 혼동하지 않았는가?
- 출생 코호트 경계가 빠지지 않았는가?
- 개정 전 기간에 종전 규칙을 적용하는 경과조항을 반영했는가?
- 공식 시행 정책과 향후 시나리오를 분리했는가?
- 모든 변경값에 공식 근거가 있는가?

### 5.6 AI의 출력 파일

반드시 다음 두 파일만 결과물로 제공한다.

#### `policy-update.json`

- `policy-update.schema.json`을 만족하는 순수 JSON
- 주석, Markdown 코드 펜스, 실행 스크립트를 포함하지 않음
- 기준 정책 ID와 새 정책 ID 포함
- 변경 규칙만 포함
- 출처와 검증 상태 포함
- 미확정 사항이 하나라도 있으면 활성화 가능한 공식 팩으로 표시하지 않음

#### `POLICY_UPDATE_REPORT.md`

최소 다음 내용을 포함한다.

```text
기준 정책 ID
새 정책 ID
정책 기준일
법적 상태
변경 규칙 목록
변경 전/후 값
각 변경의 시행일과 적용 기준일
경과조치
공식 출처 목록
확인하지 못한 사항
ENGINE_UPGRADE_REQUIRED 항목
예상 영향 범위
```

AI는 앱의 검증을 통과한다고 보장하거나 결과를 국민연금공단의 확정 산정값이라고 표현하지 않는다.

## 6. AI 출력 정책의 예시 골격

실제 필드 형식은 함께 제공된 최신 JSON Schema가 우선한다.

```json
{
  "schemaVersion": "1.0.0",
  "policyPackId": "KR-NPS-USER-20260829-001",
  "basePolicyPackId": "KR-NPS-2026.08.1",
  "createdAt": "2026-08-29T15:00:00+09:00",
  "createdBy": "AI_ASSISTED",
  "legalStatus": "ENACTED",
  "changes": [
    {
      "operation": "ADD_RULE_VERSION",
      "ruleId": "standardIncome.limits",
      "validFrom": "2026-07-01",
      "validToExclusive": "2027-07-01",
      "applicationClock": "CONTRIBUTION_MONTH",
      "value": {
        "minimumKrw": 410000,
        "maximumKrw": 6590000
      },
      "legalSourceIds": ["MOHW-NPS-LIMITS-2026"]
    }
  ],
  "legalSources": [
    {
      "id": "MOHW-NPS-LIMITS-2026",
      "publisher": "보건복지부",
      "title": "공식 자료 제목",
      "url": "https://www.mohw.go.kr/...",
      "publishedDate": "2026-...",
      "effectiveDate": "2026-07-01",
      "retrievedDate": "2026-08-29"
    }
  ],
  "unresolvedItems": [],
  "engineUpgradeRequired": []
}
```

이 예시는 구조 설명용이다. 값의 진위와 실제 필드 허용 여부는 공식 출처 및 앱이 내보낸 최신 Schema로 확인해야 한다.

## 7. 프로그램의 가져오기 절차

사용자는 `설정 > 정책 관리 > AI 정책 파일 가져오기`에서 `policy-update.json`을 선택한다.

프로그램은 다음 순서로 처리한다.

1. 파일 크기와 JSON 형식 확인
2. 실행 코드·알 수 없는 필드 차단
3. JSON Schema 검증
4. 기준 정책 ID 존재 여부 확인
5. 엔진 버전과 rule catalog 호환성 확인
6. 날짜 구간의 중복·공백 검사
7. 조건표 충돌과 우선순위 검사
8. 비율·금액·개월 범위 검사
9. 공식 출처 도메인과 필수 메타데이터 검사
10. 앱에 내장된 변경 불가능한 핵심 테스트 실행
11. 기존 Golden Test 실행
12. 합성 샘플로 변경 전후 영향 분석
13. 사용자에게 변경 내역과 경고 표시
14. 사용자 최종 승인 후 별도 버전으로 설치

다음 경우 활성화를 거부한다.

- Schema 오류
- 알 수 없는 rule ID
- 기간 충돌
- 필수 정책 구간 공백
- 엔진 업그레이드 필요
- 핵심 회귀 테스트 실패
- `TODO_LEGAL` 또는 미확정 필수 항목 존재
- 기준 정책과 무관한 대량 변경
- 공식 정책과 시나리오가 한 파일에 혼합됨

## 8. 검증 실패 시 AI와 직접 수정하는 절차

가져오기 검증에 실패해도 개발자에게 문의하지 않고 AI에 다시 수정을 맡길 수 있어야 한다.

프로그램은 `AI 수정 요청 키트 내보내기` 버튼으로 다음 ZIP을 만든다.

```text
NPS_POLICY_AI_FIX_KIT.zip
├─ AI_POLICY_FIX_GUIDE.md
├─ rejected-policy-update.json
├─ validation-errors.json
├─ policy-update.schema.json
├─ allowed-rule-catalog.json
└─ current-policy.snapshot.json
```

`validation-errors.json` 예:

```json
{
  "validatorVersion": "1.3.2",
  "errors": [
    {
      "code": "POLICY_PERIOD_OVERLAP",
      "ruleId": "standardIncome.limits",
      "jsonPointer": "/changes/1",
      "message": "2026-07-01부터 2027-01-01까지 기존 규칙과 기간이 겹칩니다.",
      "expected": "기존 기간 종료 또는 새 기간 시작 경계를 조정하세요."
    }
  ]
}
```

사용자가 AI에 보낼 요청:

```text
첨부한 AI_POLICY_FIX_GUIDE.md와 validation-errors.json을 기준으로
rejected-policy-update.json의 오류만 수정해 주세요.
법적 값이나 출처를 임의로 바꾸지 말고, 수정할 근거가 부족하면 TODO_LEGAL로 남겨 주세요.
수정된 policy-update.json과 변경 설명만 돌려주세요.
```

AI가 수정한 파일을 다시 검사하고, 오류가 없어질 때까지 같은 절차를 반복한다. 수정 키트에도 개인정보와 실제 시뮬레이션 데이터는 포함하지 않는다.

## 9. 신뢰 수준 표시

AI가 파일 안에서 스스로 “검증됨”이라고 써도 앱은 그것을 신뢰하지 않는다. 신뢰 수준은 앱이 파일 출처와 검증 경로에 따라 부여한다.

| 앱 표시 | 의미 |
|---|---|
| `내장 검증 정책` | 개발자가 서명하여 앱과 함께 제공한 정책 |
| `사용자 가져오기·검증 통과` | AI 보조 파일이 구조·회귀 검증을 통과하고 사용자가 승인 |
| `사용자 시나리오` | 법적 확정값이 아닌 가정 |
| `초안·활성화 불가` | 미확정 또는 검증 실패 항목 존재 |

`사용자 가져오기·검증 통과`는 앱의 기술 검증을 통과했다는 뜻이지, 국민연금공단이 정책 내용을 인증했다는 뜻은 아니다.

## 11. 테스트 보안

AI가 만든 정책 파일이 앱의 검증 기준을 약화시키지 못하게 한다.

- 핵심 테스트와 허용 범위는 앱 본체에 내장한다.
- 정책 팩은 핵심 테스트를 삭제·수정·건너뛸 수 없다.
- AI가 제안한 테스트는 추가 테스트로만 실행한다.
- 정책 파일 안의 코드, 명령, DLL, 스크립트는 실행하지 않는다.
- JSON 수식은 앱이 허용한 제한된 연산만 평가한다.
- 파일 경로, 네트워크 URL 호출, 환경변수 접근 기능은 정책 언어에 제공하지 않는다.

## 12. 개인정보 보호 확인

AI 업데이트 키트와 정책 출력은 공개 제도 정보만 다룬다.

프로그램은 내보내기 전에 다음 키가 포함되지 않았는지 검사한다.

```text
name
birthDate
income
standardMonthlyIncome
premium
contributionHistory
expectedPension
survivorPension
profileId
reportPath
```

실제 구현에서는 단순 키 이름 차단뿐 아니라, 내보내기 모델 자체를 공개 정책 전용 DTO로 만들어 개인정보 객체가 직렬화 경로에 들어올 수 없게 한다.

## 13. 롤백과 과거 결과

- 새 정책은 기존 정책을 덮어쓰지 않고 별도 버전으로 설치한다.
- 활성화는 현재 정책 포인터만 바꾼다.
- 문제 발생 시 이전 정책을 선택하여 즉시 롤백한다.
- 이미 계산한 결과에는 사용한 정책 ID와 콘텐츠 해시가 남는다.
- 과거 결과는 자동 재계산하지 않는다.
- 최신 정책으로 재계산할 때는 변경 전후 비교를 제공한다.

## 14. 이 방식의 한계

다음 상황은 AI 정책 파일만으로 처리하지 않는다.

- 앱이 알지 못하는 새로운 급여 종류 신설
- 새로운 개인정보 입력이 필요한 자격조건
- 월 단위가 아닌 새로운 시간 계산 방식
- 현재 허용된 정책 수식으로 표현할 수 없는 산식
- 결과 모델의 구조 변경이 필요한 법 개정

AI는 이 경우 `engineUpgradeRequired`에 사유를 기록해야 하며, 프로그램은 정책 활성화를 거부하고 본체 업데이트가 필요하다고 안내한다.

이 경우에만 프로그램 본체가 이해할 수 없는 제도 구조가 생긴 것이므로 새 프로그램 버전이 필요하다. 단순 정책값·기간·기존 조건식 변경 때문에 개발자에게 연락하도록 만들면 안 된다.

## 15. 권장 제품 문구

```text
이 정책은 사용자가 AI의 도움을 받아 가져온 개인용 정책입니다.
프로그램의 구조·충돌·회귀 검증을 통과했지만 국민연금공단이 인증한 자료는 아닙니다.
실제 보험료와 급여는 신청 시점의 법령 및 국민연금공단 산정 결과가 우선합니다.
```

## 16. 완료 기준

- 사용자가 앱에서 개인정보 없는 AI 업데이트 키트를 받을 수 있다.
- 일반적인 AI 서비스에 키트와 공식 자료를 전달해 표준 JSON을 받을 수 있다.
- 앱은 인터넷 연결 없이 AI 생성 정책을 검증하고 설치할 수 있다.
- AI가 만든 정책은 실행 코드를 포함할 수 없다.
- 핵심 검증은 정책 파일로 변경할 수 없다.
- 변경 전후 값, 시행일, 적용 기준일, 출처, 영향이 활성화 전에 보인다.
- 사용자가 언제든 이전 정책으로 돌아갈 수 있다.
- 모든 결과에 정책 ID와 해시가 기록된다.
- 정책 업데이트 과정에 사용자 연금정보가 포함되지 않는다.
- 최초 배포 후 개발자나 별도 운영 서버가 없어도 사용자가 AI와 정책 작성·오류 수정·활성화를 완료할 수 있다.
