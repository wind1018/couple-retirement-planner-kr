# 독립 실행형·개인정보 보호 아키텍처

> 대상: 국민연금 부부 종합 시뮬레이터
>
> 기본 원칙: 개인의 연금·소득·가입 이력은 사용자의 PC 밖으로 전송하지 않는다.

## 1. 권장 배포 형태

Windows용 독립 실행 데스크톱 앱으로 배포한다.

```text
NpsSimulator.exe
   ├─ Native Desktop UI
   ├─ Simulation Engine
   ├─ Policy Engine
   ├─ Local encrypted storage
   ├─ Local PDF/CSV export
   └─ Offline policy-pack importer
```

- 웹 서버를 실행하지 않는다.
- 브라우저나 `localhost` 접속이 필요 없다.
- 회원가입과 로그인이 없다.
- 인터넷 연결이 없어도 입력, 계산, 비교, 보고서 출력이 모두 가능하다.
- .NET Runtime을 포함한 self-contained 방식으로 배포하여 별도 런타임 설치 없이 실행되게 한다.

Windows 전용 1차 버전은 `.NET 데스크톱 + WPF`가 가장 단순하다. 향후 macOS/Linux까지 동일 앱을 제공할 계획이 명확하면 UI만 Avalonia 같은 크로스플랫폼 데스크톱 프레임워크로 교체할 수 있도록 도메인·정책 엔진을 UI와 분리한다.

## 2. 프라이버시 기본값

앱의 초기 상태는 다음과 같아야 한다.

| 항목 | 기본값 |
|---|---|
| 사용자 계정 | 없음 |
| 서버 저장 | 없음 |
| 자동 동기화 | 꺼짐/미제공 |
| 텔레메트리·분석 SDK | 없음 |
| 광고·추적 SDK | 없음 |
| 자동 저장 | 꺼짐 |
| 최근 파일 목록 | 저장 안 함 |
| 입력값 로그 | 금지 |
| 오류 보고 자동 전송 | 금지 |
| 외부 CDN·웹폰트 | 금지 |
| 네트워크 없이 계산 | 가능 |

“로컬 앱”이어도 외부 분석 도구나 자동 오류 보고가 데이터를 전송할 수 있으므로, 단순 설정이 아니라 해당 SDK와 전송 코드를 빌드에서 제외한다.

## 3. 데이터 보관 모드

### 3.1 기본: 일회성 계산 모드

- 입력값과 계산 결과를 실행 중 메모리에만 둔다.
- 앱을 닫을 때 저장 여부를 묻는다.
- 저장하지 않으면 개인 입력을 파일로 남기지 않는다.
- 비정상 종료 복구를 위한 자동 임시저장은 기본적으로 하지 않는다.

민감정보 보호 관점에서 이 모드를 최초 실행 기본값으로 권장한다.

### 3.2 선택: 내 PC에 암호화 저장

사용자가 명시적으로 저장을 선택한 경우에만 저장한다.

- Windows 사용자 계정에 귀속되는 암호화 키를 사용한다.
- 데이터 파일은 사용자별 앱 데이터 디렉터리에 둔다.
- 파일명에 이름, 생년월일, 연금액을 넣지 않는다.
- DB 또는 문서 전체를 인증된 암호화 방식으로 보호한다.
- 무결성 검증 실패 시 파일을 읽지 않고 손상 경고를 표시한다.
- 앱 잠금용 추가 비밀번호는 선택 기능으로 제공할 수 있다.

권장 경로 예:

```text
%LOCALAPPDATA%\NpsSimulator\
├─ profiles\        # 암호화된 사용자 저장 파일
├─ policies\        # 공개 정책 팩, 개인정보 없음
├─ reports\         # 사용자가 저장을 선택한 경우에만
└─ logs\            # 개인정보가 제거된 로컬 진단 로그
```

Windows의 사용자별 파일 권한만으로는 충분하지 않다. 다른 관리자 계정, 디스크 복제, 백업 노출 가능성을 줄이기 위해 저장 내용 자체도 암호화한다.

### 3.3 휴대용 모드

USB 등에 앱과 데이터를 함께 넣는 portable 모드는 편리하지만 분실 위험이 크다.

- 기본 배포에서는 비활성화한다.
- 제공한다면 비밀번호 기반 암호화를 필수로 한다.
- 실행파일 옆에 평문 JSON/SQLite를 저장하지 않는다.
- 휴대용 모드 사용 시 분실 위험을 명확히 경고한다.

## 4. 저장하지 않아야 할 정보

- 주민등록번호
- 공동인증서·금융인증서 파일 또는 비밀번호
- 국민연금공단 로그인 정보
- 계좌번호
- 원본 문서가 필요하지 않은 경우의 전체 공단 PDF/스크린샷
- 개인 입력값이 포함된 진단 로그·크래시 덤프

계산에는 생년월일이 필요하지만 주민등록번호는 필요하지 않다. 이름도 필수가 아니라 `본인`, `배우자` 같은 별칭으로 충분하다.

## 5. 정책 업데이트와 개인정보의 분리

정책 팩은 법령·고시·계산 규칙만 담고 개인정보를 포함하지 않는다.

### 기본 업데이트 방식: 오프라인 가져오기

1. 사용자가 공식 배포처에서 `.npspolicy` 파일을 받는다.
2. 앱의 `정책 파일 가져오기`에서 파일을 선택한다.
3. 앱이 스키마, 해시, 전자서명, 엔진 호환성을 로컬에서 검증한다.
4. 변경 영향 예시를 표시한다.
5. 사용자가 승인하면 다음 계산부터 적용한다.
6. 문제 발생 시 이전 정책 팩으로 즉시 롤백한다.

이 과정에서 사용자 프로필과 시뮬레이션 결과는 외부로 전송되지 않는다.

### 선택 업데이트 방식: 정책 버전 확인만 허용

자동 확인 기능을 제공하더라도 다음 원칙을 지킨다.

- 기본값은 꺼짐이다.
- 공개된 현재 정책 팩 버전만 조회한다.
- 요청에 사용자 ID, 입력값, 생년월일, 소득, 계산 결과를 넣지 않는다.
- 정책 다운로드 모듈은 사용자 데이터 저장소를 읽을 권한이 없어야 한다.
- 다운로드 후 검증과 활성화는 로컬에서 수행한다.
- 자동 확인을 끄면 앱의 모든 핵심 기능이 그대로 동작한다.

구조적으로 `PolicyUpdater`가 `ProfileRepository`와 `SimulationResult`를 참조하지 못하게 프로젝트 의존성을 분리한다.

```text
PolicyUpdate.Infrastructure
    ↓ 공개 정책 팩만 전달
Policy.Application

Privacy-sensitive projects
Profile.Storage ← Simulation.Application

금지: PolicyUpdate.Infrastructure → Profile.Storage
```

## 6. 보고서·CSV 내보내기 보호

PDF와 CSV는 앱 밖으로 나가는 순간 사용자가 직접 관리하는 민감 파일이 된다.

- 저장 전에 포함될 개인정보를 미리 보여준다.
- 기본 파일명은 `연금시뮬레이션_YYYYMMDD.pdf`처럼 익명으로 만든다.
- 이름·생년월일의 전체 표시 여부를 선택하게 한다.
- PDF 메타데이터의 작성자 필드에 사용자 이름을 넣지 않는다.
- 임시 PDF를 디스크에 만들지 않고 가능한 한 메모리에서 생성한다.
- 인쇄 후 자동 생성된 임시파일을 남기지 않는다.
- 내보내기 완료 후 파일의 실제 저장 위치를 명확히 알려준다.
- “민감정보 포함 파일” 경고를 표시한다.

PDF 자체 비밀번호는 선택 기능으로 제공할 수 있지만, 지원 환경에 따라 호환성과 암호화 수준을 명확히 안내해야 한다.

## 7. 로그와 오류 처리

- 보험료, 소득, 연금액, 생년월일, 이름을 로그에 기록하지 않는다.
- 식별 가능한 전체 입력 객체를 직렬화해 로그에 남기지 않는다.
- 오류에는 규칙 ID, 엔진 버전, 예외 코드만 기록한다.
- 크래시 보고서는 자동 업로드하지 않는다.
- 사용자가 지원을 원할 때만 개인정보 제거된 진단 묶음을 직접 내보낸다.
- 정책 팩 해시와 앱 버전은 진단에 포함할 수 있다.

로그 예:

```text
허용: SIMULATION_FAILED code=POLICY_RULE_CONFLICT ruleId=backPayment.rate
금지: 홍길동, 1965-01-02, 월소득 4,500,000원 계산 실패
```

## 8. 삭제와 복구

- 프로필별 삭제와 전체 사용자 데이터 삭제를 제공한다.
- 삭제 대상 경로와 정책 팩 보존 여부를 보여준다.
- 정책 팩은 공개 데이터이므로 개인정보 삭제와 별도로 처리한다.
- 사용자가 만든 PDF/CSV는 앱 관리 경로 밖에 있을 수 있으므로 자동 삭제되지 않는다는 점을 안내한다.
- 백업은 사용자가 명시적으로 실행할 때만 암호화된 파일로 만든다.
- 복원 시 파일 무결성과 정책 버전 호환성을 확인한다.

SSD·클라우드 백업·Windows 파일 기록 등에서는 단순 파일 삭제만으로 모든 복제본의 물리적 제거를 보장할 수 없으므로 “완전 소거”라고 표현하지 않는다.

## 9. 화면에서 보여줄 개인정보 상태

앱 상단 또는 설정에 항상 현재 상태를 표시한다.

```text
개인정보 보호 상태
● 오프라인 계산
● 자동 저장 꺼짐
● 외부 전송 없음
● 현재 데이터: 저장되지 않음
정책: KR-NPS-2026.08.1 (서명 확인됨)
```

저장된 프로필을 열었을 때는 다음처럼 바뀐다.

```text
현재 데이터: 이 Windows 사용자 계정에 암호화 저장됨
마지막 저장: 2026-08-29 14:20
```

“안전합니다” 같은 포괄적 표현 대신 실제 동작 상태를 구체적으로 보여준다.

## 10. 프로젝트 구조

```text
src/
├─ NpsSimulator.Domain/              # 개인정보 저장·네트워크 의존성 없음
├─ NpsSimulator.Policy/              # 정책 로딩·검증·해석
├─ NpsSimulator.Simulation/          # 월별 계산·전략 비교
├─ NpsSimulator.Application/         # 유스케이스
├─ NpsSimulator.Storage/             # 암호화된 로컬 저장
├─ NpsSimulator.Reporting/           # 로컬 PDF/CSV
├─ NpsSimulator.PolicyUpdate/        # 선택적 공개 정책 다운로드
└─ NpsSimulator.Desktop/             # WPF 데스크톱 UI

tests/
├─ Domain.Tests/
├─ Policy.Tests/
├─ Simulation.Tests/
├─ Storage.Security.Tests/
├─ Privacy.Architecture.Tests/
└─ Golden.Tests/
```

의존성 규칙:

- Domain, Policy, Simulation은 네트워크 라이브러리를 참조하지 않는다.
- PolicyUpdate는 Profile Storage를 참조하지 않는다.
- Reporting은 네트워크로 업로드하지 않는다.
- Desktop UI만 각 application service를 조합한다.

아키텍처 테스트에서 이 의존성 금지 규칙을 자동 검사한다.

## 11. 독립 실행 배포

권장 배포물은 두 가지다.

### 설치형

- 코드 서명된 설치 패키지
- 시작 메뉴 등록
- 사용자별 앱 데이터 디렉터리 사용
- 앱 업데이트와 정책 업데이트를 별도 취급

### 무설치형

- 압축을 풀고 실행하는 self-contained 배포
- .NET Runtime 별도 설치 불필요
- 사용자 데이터는 실행파일 옆이 아니라 사용자별 앱 데이터 디렉터리에 저장
- 휴대용 저장은 사용자가 별도로 활성화해야 함

예시 publish profile의 핵심 속성:

```xml
<PropertyGroup>
  <RuntimeIdentifier>win-x64</RuntimeIdentifier>
  <SelfContained>true</SelfContained>
  <PublishSingleFile>true</PublishSingleFile>
</PropertyGroup>
```

실제 UI·PDF 라이브러리의 단일 파일 호환성을 빌드에서 검증하고, 필요하면 단일 EXE 대신 서명된 폴더형 self-contained 패키지를 사용한다. 사용자 관점에서 별도 서버와 런타임 설치가 없다는 목표는 두 방식 모두 충족한다.

## 12. 보안 테스트 완료 기준

- 인터넷을 차단한 PC에서 전체 시뮬레이션과 PDF 생성이 된다.
- 기본 실행 후 앱을 닫았을 때 사용자 입력 파일이 생성되지 않는다.
- 저장 파일에서 이름·생년월일·금액 평문을 검색해도 나오지 않는다.
- 다른 Windows 사용자 계정에서 저장 파일을 열 수 없다.
- 변조한 정책 팩을 가져오면 설치를 거부한다.
- 정책 업데이트 요청에 사용자 입력이 포함되지 않는다.
- 로그와 오류 파일에 민감 필드가 없다.
- 공식 배포물에 텔레메트리·광고·분석 SDK가 없다.
- PDF 임시파일이 남지 않는다.
- 삭제 기능이 앱이 관리하는 프로필과 로컬 로그를 제거한다.

## 13. 최종 권고

이 프로젝트는 웹 서비스보다 **Local First가 아니라 Local Only를 기본값**으로 잡는 것이 적합하다.

권장 1차 제품 정의:

```text
Windows 독립 실행 앱
+ 서버 없음
+ 계정 없음
+ 네트워크 없이 전체 계산 가능
+ 기본값은 저장 안 함
+ 선택 저장 시 사용자 계정 기반 암호화
+ 정책 팩은 개인정보와 완전히 분리
+ 오프라인 파일 가져오기로 정책 업데이트 가능
+ 모든 계산 결과에 정책 버전과 근거 기록
```

향후 자동 정책 확인 기능을 추가하더라도 선택 기능으로 두고, 개인 입력을 다루는 계산·저장 계층과 코드 및 권한 수준에서 분리해야 한다.

개발자의 앱 재배포 없이 사용자가 AI를 통해 개인용 정책 팩을 생성·가져오는 상세 절차는 `docs/POLICY_UPDATE_WITH_AI.md`를 따른다.
